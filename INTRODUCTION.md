The project currently open in the workspace is a userspace thread library called **libapth**. Its core idea is to generate a larger number of userspace threads (called *apth*) on top of multiple pthread‑based workers. Each worker can run multiple apth workloads, while each apth still strives to provide the upper‑layer application with the abstraction of an independent thread, while minimizing kernel‑user space context switches.

Furthermore, the library aims to avoid system calls as much as possible to reduce kernel‑user context switches.  
It also seeks to improve I/O efficiency: when some apth are waiting for I/O, the scheduler can dispatch other workloads to the CPU, keeping the CPU busy with useful work instead of busy‑waiting. This increases CPU utilization while still preserving the original I/O semantics and abstraction for the upper‑layer application.

Most type definitions and function declarations are located in `src/internal_types.h` and `src/internal_funcs.h`.  
Each pthread worker runs a `scheduler_routine` (its behavior is described in `src/internal/apth_sched.c`). Inside the scheduler there are multiple `apth_thqueue_t` queues (implemented in `src/internal/apth_thqueue.c`) that hold apth in different states. The `scheduler_routine` continuously takes the next apth from the *ready queue*, switches context to it, and waits for the context to be returned to the scheduler (via an explicit call to `apth_yield`, termination, cancellation, or waiting for an event). Based on the thread’s new state, the scheduler then pushes it into the appropriate queue.

After that, the scheduler runs `apth_sched_eventmanager` (defined in `src/internal/apth_event.c`), which checks whether any apth in the scheduler’s *waiting queue* have had the event they are waiting for satisfied. If so, those apth are moved to the *waked queue*.

To support the library’s implementation and improve I/O efficiency, a set of libc functions and system calls—primarily I/O‑related ones—are hooked in `src/internal/apth_syscall.c`. When these functions would normally block, they instead detect that the condition is not yet met (e.g., a file descriptor is temporarily not writable) and quickly switch back to the scheduler. The scheduler can then dispatch the next runnable apth onto the CPU core. At program runtime, using `LD_PRELOAD` with this library redirects the application’s I/O functions to the library’s versions. The `apth_sched_eventmanager` in `src/internal/apth_event.c` must also be as efficient as possible to detect occurred events promptly.
